# ZSK Router

## 目的

只让用户面对一个入口，负责把自然语言任务交给正确的内部职责。Router 只编排，不把客户差异写回共享 Skill，也不直接拼接任一后端的凭据或物理路径。

## 当前阶段边界

客户已明确调取 `zsk-router` 后，只要自然语言表达“创建 / 新建 / 搭建知识库”，就进入首次建库向导；不要求固定说法。客户说“把资料入库”时，进入资料路由。首次绑定时在 06 让客户一次选择“主动提交即允许私有保存原件”或“敏感原件逐次确认”，以后按该项目偏好执行，不再逐份重复询问。资料先由 `zsk-ruku` 统一转为可读 Markdown：MD、TXT、严格 CSV 为轻量本地处理，JSON、HTML/HTM、DOCX、PPTX、XLSX、PDF 使用本机 Microsoft MarkItDown。旧版二进制 Office、图片、音视频等其他格式准确停止。

PDF/PPTX 默认仍走轻量文字入库。只有资料的页面版式、图表、截图或完整视觉本身影响含义，或客户已配置“保留完整每页”，Router 才启用通用页级证据模式。该模式以 300 DPI 保存完整页图，先提取逐页原生文字；图片、图表、SmartArt 或 PDF 视觉对象可能承载额外信息时，才运行三次本地 OCR。OCR 必须至少两次高度一致，不能用单次高置信度或部分相似冒充完整验证。任一页仍无法稳定提取时，整份资料返回 `file_quality_insufficient`，不写入 01、02、03、04 或 05，并提示上传高清 PDF 或原始文件。该模式不包含行业特例、图片理解或猜测式图文对应。

来源已登记、隐私检查完成后，读取 06 中的客户偏好。默认由 AI 按内容单元做语义识别，不要求客户选择“放 03、04 还是 05”：可核验的业务事实交给 `zsk-zhishi`，可迁移的做事或表达方法交给 `zsk-duibiao`，与绑定主体有关的确认事实、运营设定或候选素材交给 `zsk-profile`。同一份资料可以拆成多个内容单元并分别进入 03、04、05；每个单元都保留同一个 `source_id` 和片段说明。

分类本身不确定时保留在 01 并标记“待路由”，不写 02，也不反复让客户选目录。只有隐私、权限、归属、版本、主体冲突、文件损坏、转换失败、写入失败或回读失败才进入 02。客户可在 06 把默认“自动分类”改为“写入前预览”；这是项目级偏好，不写回共享 Skill。

同行内容进入 04 时，由 `zsk-duibiao` 保留选题价值、观点、推进关系、细节作用与客户适配依据；结构和总方法论保留选择条件、各段作用及组合方式。不能把所有材料压成几个短机制，也不能把同行的故事、身份或数字变成客户事实。下游用户没有给对标时，这两类资产共同帮助 Content Agent 从一段想法展开；ZSK 只负责准备和说明资料，不替代内容工作流的方向确认与写作。

## 宿主与依赖准备

安装、首次连接或依赖检查失败时，先读 [宿主接入与按需依赖](references/host-setup.md)。用户只需提供 ZSK 仓库地址；优先复用当前宿主已提供的飞书 CLI 和身份，确实缺失时才按 https://github.com/larksuite/cli 官方说明补齐。非 Codex 宿主必须核实持久 Skills 目录，不猜路径、不覆盖内置 CLI。

创建知识库不等待 MarkItDown 下载。其 Skill 说明随组合安装；转换程序只在首次富文档入库时按实际格式检查，已可用则零下载，缺失才补依赖。普通 MD/TXT/CSV 不依赖转换程序。宿主未提供授权 scope 清单时，连接检查不能宣称写权限已验证；创建预览说明此限制，真实操作拒绝即停止。

## 首次建库向导

首次使用不要求客户先准备飞书链接、客户名称或 Obsidian Vault。只询问缺失项：后端（飞书或 Obsidian）和知识库名称；Obsidian 再确认保存位置。客户已给出的信息不得重复追问。

- 飞书：先检查 lark-cli、用户身份和可获取的权限信息；宿主管理身份时按接入规则如实标注未预验证的写权限。未连接时显示“连接我的飞书”步骤，连接完成后再检查；未通过前零写入。通过后才创建私有空间、01—07、AGENTS、README、基础清单和预置口播结构库，并回读。全部完成后才能说“知识库已创建”。
- Obsidian：默认建议 macOS 使用 `~/Documents/知识库名称`，Windows 使用 `C:\\Users\\当前用户\\Documents\\知识库名称`；不默认写入桌面、保险库或隐藏目录。必须展示完整目标路径，让客户确认、改位置或取消后才创建。
- 创建成功后，在 06 create-only 生成基础 `content-source-v1` Manifest 与空 Profile 索引并回读；这只是知识库自描述，不登记宿主默认 binding，也不代表 Content 已安装。
- 新建库统一走 `shared.stage11_bootstrap.FirstRunBootstrap`：在原有建库预览中列出完整口播结构库，将包版本与摘要绑定到同一次确认。在 04 创建独立副本、在 06 记录安装版本；骨架、基础清单、预置文档全部回读后才报告成功。资源和两种后端规则见 [口播结构预置](references/oral-structure-preset.md)。
- 旧库检查、入库和补骨架不得自动安装或更新口播结构；同名冲突停止，保留客户修改。底层 `Stage2Router` 仅负责骨架，不得用其成功结果代替完整首次建库。
- 用户明确要求连接 Content 工作流时，读取 [公共 Content 来源合同](references/content-source-v1.md)，先做零写入预览；真人确认后才登记公共 Registry。旧口播 v2 交接仍按 [兼容规则](references/content-koubo-slim-handoff.md) 保留。
- 当前运行环境缺少建库或连接能力时，准确说明缺少什么并停止；不得伪称已经创建，也不得把客户推回“你自己先随便建一个库”的技术流程。

## 必须遵守

- 一次执行只能解析一个稳定绑定；绑定冲突、权限不足、依赖缺失和读回失败都 fail closed。
- 公开调用只进入 `zsk-router`；来源登记、业务知识、内容方法和 Profile 由内部职责承接。
- `source_id` 由原件 SHA256 确定，只留在元数据中用于防重和回链；客户看到的来源目录、原件、可读版和页图使用“日期＋中文标题”的人类可读名称。原件保存按 06 的项目级偏好执行；不扫描或读取未提交的本机文件。OCR 文字必须再次经过同一隐私检查和脱敏后才能写入。
- `03`、`04`、`05`、`indexed_only` 与 `02` 是可解释路由结果，不使用数字评分替代准入 Gate。
- 创建前确认必须绑定预览、客户绑定、后端、模板版本和有效期；错误、过期或已使用的确认零写入。
- Content 工作流绑定确认必须匹配当前预览摘要；公众号可用 Obsidian/飞书，口播只允许 Obsidian。Registry、Manifest、Profile 索引或客户绑定冲突时停止，不得扫描电脑或覆盖旧配置。
- 同名异构、重复根节点、空规则或不可读规则必须停止；客户改过的 AGENTS、README、06 不覆盖，仍可继续入库。
- Obsidian 相对路径、`..`、软链接、特殊对象和未知根对象必须停止，绝不回退个人 Vault。
- MarkItDown 产生但未落地的本地图片占位必须移除，不能让 Obsidian 或飞书显示破图。完整页证据模式下，Obsidian 可读版嵌入真实相对页图；飞书来源 Docx 同时写自动验证的页文字与高清原页图，并回读正文、图片数量、尺寸和远端媒体 SHA256。
- 旧版二进制 Office（`.doc/.xls/.ppt`）、零散图片、音视频和正式资产生产不在当前范围。PDF/PPTX 可选择完整页证据，但默认按 06 偏好询问；本地页图 OCR 属于该模式，图片向量检索、图片描述、猜测式图文对应和无确认自动发布仍不在范围。

## 输出

返回当前状态、路由结果、稳定对象引用、原因码和下一步；不把测试通过说成真实后端已连接，不把阶段 1 说成项目首发完成。
