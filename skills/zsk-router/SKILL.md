# ZSK Router

## 目的

只让用户面对一个入口，负责把自然语言任务交给正确的内部职责。Router 只编排，不把客户差异写回共享 Skill，也不直接拼接任一后端的凭据或物理路径。

## 当前阶段边界

客户已明确调取 `zsk-router` 后，只要自然语言表达“创建 / 新建 / 搭建知识库”，就进入首次建库向导；不要求固定说法。客户说“把资料入库”时，进入资料路由。资料先由 `zsk-ruku` 统一转为可读 Markdown：MD、TXT、严格 CSV 为轻量本地处理，JSON、HTML/HTM、DOCX、PPTX、XLSX、PDF 使用本机 Microsoft MarkItDown；只产生 01 登记或 02 安全异常。旧版二进制 Office、图片、音视频等其他格式准确停止。

PDF/PPTX 默认仍走轻量文字入库。只有资料的页面版式、图表、截图或完整视觉本身影响含义，或用户明确要求“保留完整每页”，Router 才提出启用通用页级证据模式；必须先说明会额外保存完整页图并取得原件保存授权。该模式不包含任何行业特例，也不自动启用 OCR、图片理解、图文猜配或发布。

来源已登记、处理权和隐私均通过后，按来源角色继续：`business_knowledge` 交给 `zsk-zhishi` 写 03 知识卡；`reference_method` 交给 `zsk-duibiao` 写 04 方法卡；`profile_material` 交给 `zsk-profile` 写 05 三层主 Profile。角色不明、主体不一致或不满足准入 Gate 时停在 01/02，不凭评分或猜测进入 03/04/05。

## 首次建库向导

首次使用不要求客户先准备飞书链接、客户名称或 Obsidian Vault。只询问缺失项：后端（飞书或 Obsidian）和知识库名称；Obsidian 再确认保存位置。客户已给出的信息不得重复追问。

- 飞书：先检查 lark-cli、用户身份和创建知识空间权限。未连接时显示“连接我的飞书”步骤，连接完成后再检查；未通过前零写入。通过后才创建私有空间、01—07、AGENTS、README，并回读。只有空间链接和九个根对象都真实返回，才能说“知识库已创建”。
- Obsidian：默认建议 macOS 使用 `~/Documents/知识库名称`，Windows 使用 `C:\\Users\\当前用户\\Documents\\知识库名称`；不默认写入桌面、保险库或隐藏目录。必须展示完整目标路径，让客户确认、改位置或取消后才创建。
- 创建成功后，保留新知识库自己的 06 使用说明，不写回共享 Skill；返回飞书链接或 Obsidian 路径，并提示“知识库已创建，可以开始上传资料”。后续运行由宿主保存并传入该位置；未实现持久绑定时不得声称已自动记住。
- 当前运行环境缺少建库或连接能力时，准确说明缺少什么并停止；不得伪称已经创建，也不得把客户推回“你自己先随便建一个库”的技术流程。

## 必须遵守

- 一次执行只能解析一个稳定绑定；绑定冲突、权限不足、依赖缺失和读回失败都 fail closed。
- 公开调用只进入 `zsk-router`；来源登记、业务知识、内容方法和 Profile 由内部职责承接。
- `source_id` 由原件 SHA256 确定；未完成权限和隐私 Gate 前不得保存原件。
- `03`、`04`、`05`、`indexed_only` 与 `02` 是可解释路由结果，不使用数字评分替代准入 Gate。
- 创建前确认必须绑定预览、客户绑定、后端、模板版本和有效期；错误、过期或已使用的确认零写入。
- 同名异构、重复根节点、空规则或不可读规则必须停止；客户改过的 AGENTS、README、06 不覆盖，仍可继续入库。
- Obsidian 相对路径、`..`、软链接、特殊对象和未知根对象必须停止，绝不回退个人 Vault。
- 旧版二进制 Office（`.doc/.xls/.ppt`）、零散图片、音视频和正式资产生产不在当前范围。PDF/PPTX 可选择完整页证据，但默认关闭；OCR、图片向量检索、图文自动对应和自动发布仍不在当前范围。

## 输出

返回当前状态、路由结果、稳定对象引用、原因码和下一步；不把测试通过说成真实后端已连接，不把阶段 1 说成项目首发完成。
